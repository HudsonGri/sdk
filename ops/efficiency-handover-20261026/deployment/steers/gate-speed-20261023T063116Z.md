## Required cross-OS dispatcher payload

`gate-e2e.ps1` must do the following, and persist each raw command, exit code,
wall time, Cargo artifact JSON, artifact/source SHA-256 and final receipts:

1. Resolve the checkout commit AND tracked tree (including the merged batch),
   inventory/manifest and lockfile hashes. Reject a dirty tracked checkout.
   Create an isolated per-run source snapshot and per-lane target cache; never
   reset an unrelated worktree. Keep exported archives outside the synced tree.
2. Linux first: via `bs.ps1 --env BUILD_SLOT_BUILDBOX_HOST=bb2`, build only
   `graphcoder`, `harness-mock-model`, and required acceptance artifacts with
   `--locked`; install the PTY frozen Bun lock without scripts; run helpers and
   `node scripts/graphcoder-e2e/serial.mjs "$graphcoder" "$mock"`. Also run the
   affected Cargo packages from `.gate-selection.json`, using actual Cargo JSON
   executable paths and nonempty libtest results. Compilation is outside each
   test's existing ten-second budget; no stack or timeout changes.
3. macOS second: transfer that same source snapshot to a new directory on
   `ivar`, build there, then run the same helper, serial matrix and affected
   Cargo selections. PATH must include `/sbin`, `/usr/sbin`, Homebrew and Bun.
   Omitting `/sbin/mount_nfs` creates a fixture failure, not a product verdict.
4. Windows third: cross-build MSVC artifacts on bb2, including the unchanged
   C# ConPTY helper and `scripts/graphcoder-e2e/owned-process.cs` lifetime host
   (Roslyn with .NET Framework references on bb2). Supply the latter as
   absolute `E2E_PROCESS_HOST`; verify
   copied hashes. Run each affected-crate selection through
   `bash Q:/lanes/win-test.sh PACKAGE --all-features --all-targets`; do not nest
   its fleet mutex. Then acquire `Global\AcyclicWindowsTestRun` for the helper
   tests and serial shipping matrix, one process at a time. Use
   `--test-concurrency=1`, `RUST_TEST_THREADS=1`, ReFS workspace and explicit
   NTFS root. Never invoke prepare-conpty.ps1's local Add-Type compilation.
5. Prepare the real plugin integration executable, matching `acyclic` binary,
   provider library test executable, pinned actual Codex/Claude/Pi hosts and
   filesystem N-API companion before acceptance. Wire the environment from
   the runner README. Missing artifacts, ignored host tests and zero tests
   remain failures. External libtest/Bun acceptance runs use the runner's
   process group/Job Object lifetime boundary and drain service descendants
   on normal exit and cancellation before the next suite. No credentialed
   profile is copied to a build box.
6. Validate exactly three full receipts: matching source/tree, inventory,
   manifest and lock hashes; expected OS; `qualification: true`; every case
   and required filesystem variant once; every case passes; every suite
   finite, positive and <10 s; aggregate `pass: true`; coverage has 26 mapped
   rows and empty missing/unmapped/gaps lists. Total serial matrix duration is
   separately recorded, never mistaken for a single case suite budget.
7. A missing, duplicate, truncated, stale or selected-only receipt fails.
   Continue collecting the other OS failures for diagnosis, then return
   nonzero. A known owner PR is a diagnostic annotation, not a gate exemption.

must block before the Cargo baseline can grant PASS. Run the verdict tests on
bb2. These dispatcher controls have NOT yet been executed: deployment is pending.
